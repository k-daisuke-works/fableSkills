# KPI設計・グロース分析

事業の成長を測る指標体系を設計し、データからボトルネックと打ち手を導くスキル。

## 大原則

**指標は行動を変えるためにある。** 見ても誰の行動も変わらない数字はダッシュボードの飾り。各指標に「悪化したら誰が何をするか」が紐付いて初めてKPI。また、割合と実数を必ずセットで見る（CVR 2倍でも分母10なら意味の解釈が変わる）。

## 手順

### 1. KPI体系の設計（設計依頼の場合）

**North Star Metric（NSM）の選定**
- 「顧客が価値を受け取った量」を表す1つの指標を選ぶ（例: 週次アクティブ利用、完了された取引数）。売上はNSMより遅行する結果指標
- 良いNSMの条件: 顧客価値と相関 / チームの行動で動かせる / 先行指標である

**KPIツリーへの分解**
- NSM(または売上)を掛け算・足し算で分解する（例: 売上 = 訪問 × CVR × 単価 × リピート率）
- 各葉ノードに: 現在値 / 目標値 / 担当 / 更新頻度 / 悪化時のアクション
- 指標は各チーム3〜5個まで。全部大事は何も大事じゃないのと同じ

**ファネル定義（AARRR）**
- Acquisition（獲得）→ Activation（価値の初体験）→ Retention（継続）→ Referral（紹介）→ Revenue（収益）の各段階に測定イベントを定義する
- **Activation の定義が最重要**: 「登録」ではなく「価値を体感した瞬間」（例: 最初のプロジェクト作成完了）を、データがあれば継続率との相関から特定する

### 2. 計測設計

- イベント設計表を作る: イベント名 / 発火条件 / プロパティ / 実装場所。命名規則（`対象_動詞` 等）を統一する
- 実装コードがあるプロジェクトなら、計測の実装・抜け漏れ確認まで行う
- ダッシュボードの構成案（毎日見る数字 / 週次で見る数字 / 深掘り用)を提案する

### 3. 分析（分析依頼の場合）

データ（CSV・DB・分析ツールのエクスポート）をもらい、スクリプトで分析する:

- **ボトルネック特定**: ファネル各段階の転換率を出し、業界相場・過去実績と比べて最も弱い箇所を特定する。改善インパクトは「その段階を X% 改善したときの最終成果への影響」で試算する
- **コホート分析**: 登録月別の継続率曲線を出す。平らになるか（定着する製品か）ゼロに向かうか（穴の空いたバケツか）が最重要の分岐
- **セグメント分解**: 悪化・改善の原因を、流入元・デバイス・プラン・顧客属性で分解して特定する（全体平均は原因を隠す）
- 相関と因果を区別する。因果を主張する場合はA/Bテストか自然実験の根拠を示す

### 4. 改善施策の優先順位付け

洗い出した施策を **ICE**（Impact × Confidence × Ease）でスコアリングし、上位から実験計画（仮説 / 変更内容 / 成功基準 / 必要サンプルサイズの目安 / 期間）に落とす。有意差の判定を伴う場合、サンプル不足での早期打ち切りに注意を促す。

## 注意事項

- 虚栄の指標（累計登録数・累計DL数・PV）を主KPIにしない。指摘した上で行動につながる代替を示す
- 目標値は根拠付きで置く（過去トレンド・業界ベンチマーク・逆算のいずれか）。根拠を作れない場合は「観測期間を置いてから設定」を提案する
- 分析結果は必ず「So What（だから何をする）」で締める。グラフだけの報告はしない
