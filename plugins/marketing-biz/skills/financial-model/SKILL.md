# 財務モデル・収支計画

事業の数字を前提から組み立て、スクリプトで計算・検証できる財務モデルを作るスキル。

## 大原則

**モデルの価値は前提の透明性。** すべての出力数字は「入力（前提）× 式」に遡れること。前提は1箇所に集約し、Excel的な「セルに直値」を作らない。そして単一の予測値でなく、**幅（シナリオと感度）**で答える。

## 手順

### 1. ビジネスモデルの式化

収益構造を確認し、事業を式で表す:

- サブスク: MRR = 顧客数 × ARPU、顧客数の推移 = 前月 × (1−解約率) + 新規
- 取引型: 売上 = 取引数 × 取引単価 × テイクレート
- 単発販売: 売上 = リード × CVR × 単価（+リピート率）

### 2. ユニットエコノミクス

事業全体の前に「顧客1人の採算」を先に確認する:

- **LTV**: サブスクなら 平均月次粗利 ÷ 月次解約率（簡便法）。前提の解約率に実績がない場合は業界相場を使い、出典を明記
- **CAC**: 獲得コスト合計 ÷ 新規顧客数（広告費だけでなく人件費も含めるか、範囲を明示）
- 判定の目安: LTV/CAC ≧ 3、CAC回収期間 ≦ 12ヶ月（B2B SaaSの慣行。事業特性で調整）
- ユニットエコノミクスが成立しない構造は、スケールすると赤字が拡大するだけ — その場合は先に単価・解約率・CACのどれをどこまで動かす必要があるかを示す

### 3. モデルの実装

**計算はスクリプト（Python推奨）で実装する。** 前提を辞書/設定オブジェクトに集約し、月次で3〜5年分のPLを生成する:

```
assumptions = { 初月顧客数, 月次成長率, 解約率, ARPU, 原価率, 人件費計画, 広告費, 固定費, ... }
→ 月次: 顧客数 / 売上 / 売上原価 / 粗利 / 販管費 / 営業損益 / 累計キャッシュ
```

- 出力: 月次PL表（CSV）+ 年次サマリー + 主要グラフ（顧客数・売上・累計キャッシュ曲線）
- **損益分岐点**（単月黒字化の月）と**資金の谷**（累計キャッシュの最深部 = 必要資金）を必ず算出する
- スクリプトは `tools/financial-model/` 等に残し、前提を変えて再実行できるようにする

### 4. シナリオと感度分析

- **3シナリオ**: 基本 / 保守（成長率・CVRを6〜7割に）/ 楽観。それぞれの黒字化時期と必要資金を併記
- **感度分析**: 主要前提（成長率・解約率・単価・CAC）を±20%動かしたときの最終年利益への影響を出し、**「どの変数が一番効くか」**を特定する。これが経営が集中すべき数字
- 資金調達が絡む場合: 資金の谷 × 1.5倍程度のバッファを持った調達額を提案の目安にする

### 5. 報告

①結論（黒字化時期・必要資金・成立性の評価を3行）→ ②ユニットエコノミクス → ③PLサマリー（表+グラフ）→ ④シナリオ比較 → ⑤感度分析（トルネード形式の表）→ ⑥全前提の一覧（出典・自信度付き）→ ⑦再計算の方法。

## 注意事項

- 前提に自信度ラベルを付ける: [実績] / [業界相場・出典あり] / [仮置き]。仮置きだらけのモデルはその旨を結論に明記する
- 税・減価償却・消費税等の会計処理は簡略化する場合その旨を明示し、正式な計画は税理士等の確認を推奨する
- 「計画を良く見せるための前提いじり」を求められても、根拠のない前提変更はモデルの意味を失うと伝える（シナリオとして併記する形を提案）
- 既存の実績データがあれば必ずもらい、モデルの初期値を実績でキャリブレーションする
