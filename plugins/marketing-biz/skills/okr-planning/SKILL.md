# OKR設計・目標プランニング

行動を変える目標体系（OKR）を設計し、運用まで含めて機能させるスキル。

## 大原則

**Objective は方向を示す旗、Key Result は到達の証拠。** O は定性的で鼓舞するもの、KR は定量的で解釈の余地がないもの。この分離が崩れた OKR（O が数字、KR がタスクリスト）は目標管理ではなくただの作業一覧になる。

## 手順

### 1. 前提の確認

- 期間（四半期が標準）と階層（会社 / チーム / 個人 — 最初は会社+チームの2層まで推奨）
- 上位の戦略・ミッション（OKR はそこから導かれる。存在しないなら先にそれを1文で固める）
- 現在の主要数値（ベースラインがないと KR の目標値が根拠を持たない。`growth-metrics` の成果物があれば使う）

### 2. Objective の設計

- 1期間に **O は1〜3個**（5個あるのは優先順位がないのと同じ）
- 書き方: 定性的・鼓舞的・期間内に完結（例: 「新規顧客が自力で成功できるオンボーディングにする」）
- 「今期これしか達成できないとしたら何か?」の問いで絞り込む

### 3. Key Result の設計

各 O に **KR は2〜4個**。条件:

- **結果指標であること**: 「記事を12本書く」(活動) ではなく「オーガニック経由の登録を月300件にする」(結果)。活動しか書けない場合、その活動が何を変えるはずなのかを問い直す
- **数値と期限**: 現在値→目標値の形式で（「CVR 2.1% → 3.0%」）
- **難易度**: ストレッチ目標なら達成率60〜70%が良い設計。人事評価に直結させる場合はコミット型（100%前提）と明確に区別する — **この区別を曖昧にすると全員が安全な目標しか出さなくなる**
- 品質ガード: 速度系 KR には品質系 KR を対にする（「対応時間を半減」×「満足度を維持」）

### 4. アンチパターン検査（レビューの核）

設計した/持ち込まれた OKR を以下で検査し、修正案付きで指摘する:

- [ ] KR がタスクリストになっている（「◯◯を実装する」）
- [ ] 全 KR が100%達成できそう（サンドバッギング=低め設定）または全部が非現実的
- [ ] チーム間で矛盾・依存の未調整（営業の量 KR と CS の質 KR が衝突等）
- [ ] 計測手段のない KR（誰がいつどのデータで測るか答えられない）
- [ ] BAU（通常業務）が全部 OKR に入っている — OKR は変化させたいことだけ。通常業務は健全性指標として別管理
- [ ] 上位 OKR と接続していない孤立した OKR

### 5. 運用の設計

OKR は設定より運用で死ぬ。最低限の運用をセットで設計する:

- **週次チェックイン**（15分）: 各 KR の進捗(数値) / 自信度(5段階) / 障害 / 今週やること。フォーマットを用意する
- 自信度が2週連続で下がった KR は「計画の変更」を議論する（期末まで放置しない）
- **期末の振り返り**: 達成率の採点 + 「目標設計自体の学び」（高すぎた/低すぎた/測れなかった）を次期に反映する
- 途中変更のルール: O は原則変えない、KR は前提が崩れたら公開の場で変更する

## 注意事項

- OKR がすべての組織に合うわけではない。数人のチームなら「今期の最重要目標1つ+週次確認」で十分と正直に言う
- 目標値の根拠（過去トレンド・ベンチマーク・逆算）を必ず残す。根拠のない数字は期中の判断を歪める
- 評価制度との接続は組織設計の問題を含むため、断定せず選択肢（分離推奨が一般的）とトレードオフを示す
