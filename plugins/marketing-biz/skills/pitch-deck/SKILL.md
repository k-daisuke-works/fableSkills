# ピッチデック作成

聞き手を「次のアクション」に動かすピッチ資料を設計・作成するスキル。

## 大原則

**1スライド1メッセージ、デック全体で1つのストーリー。** スライドは読ませる資料ではなく話の補助線。各スライドのタイトルだけを続けて読んで話が通る状態（タイトルのメッセージ化）を目指す。そして必ず「このピッチのゴール（次のミーティング獲得 / 投資判断 / 発注）」から逆算する。

## 手順

### 1. 前提の確認

- 用途: 資金調達（シード/シリーズA以降で焦点が変わる）/ 商談・コンペ / 社内提案 / ピッチイベント
- 形式: 対面プレゼン用（文字少なめ）か送付資料（読んで完結）か。持ち時間と枚数制限
- 聞き手が既に知っていること・懐疑的な点

### 2. ストーリー設計（スライドを作る前に）

投資家向けの標準構成（12枚前後）:

1. 表紙（1文で何の会社かわかるタグライン）
2. **課題**（誰の・どんな痛み。共感と規模感）
3. **解決策**（課題に対する自社の答え。デモ/スクリーンショット）
4. なぜ今か（市場・技術・規制の追い風）
5. 市場規模（TAM/SAM/SOM — `market-research` の成果物を使う）
6. プロダクト（動く証拠。百聞は一見に如かず）
7. **トラクション**（実績の右肩上がりグラフ。最強のスライド。無ければ検証の学びで代替）
8. ビジネスモデル（誰からどう稼ぐか+ユニットエコノミクス）
9. 競合（比較軸は自社が勝つ軸で、ただし嘘なく。「競合なし」は市場なしと聞こえるので禁句）
10. チーム（なぜ自分たちが勝てるか）
11. 財務計画・マイルストーン（`financial-model` と整合）
12. **調達額と使途**（いくらで・何を達成するか。次のラウンドにつながる目標）

商談・社内向けは「相手の課題 → 提案 → 効果(数字) → 実績・信頼 → 費用 → 進め方」に組み替える。

### 3. スライド作成

- 各スライドを「タイトル（メッセージ）/ ボディ（証拠: グラフ・図・数字）/ 備考（話すこと）」の3点セットで作る
- 数字は出典付き。グラフは1スライド1つ、伝えたい差が一目でわかる形に（`dataviz` 系のツールがあれば活用）
- 送付版と登壇版を分ける場合、登壇版から文字を削る方向で作る
- 出力形式は依頼に合わせる: Markdown構成案 / HTMLスライド（自己完結・ブラウザで表示可）/ 既存テンプレへの流し込み用テキスト

### 4. 検証とQ&A準備

- **タイトル通し読みテスト**: タイトルだけでストーリーが通るか
- **整合性チェック**: 市場規模・トラクション・財務計画・調達額の数字が相互に矛盾しないか（`business-plan` と共通の検算）
- **想定Q&A**: 聞き手が突く弱点（競合優位の持続性、CAC の根拠、チームの欠け）を先回りして10問、回答付きで用意する。答えられない質問こそ価値がある — 正直な回答方針まで作る

### 5. レビューモード

既存デックのレビューでは: ストーリーの飛躍 / 1スライド複数メッセージ / 証拠のない主張 / 数字の不整合 / 聞き手とのミスマッチ、を優先度順に指摘し、修正案を添える。

## 注意事項

- 誇張はデューデリジェンス（精査）で必ず露見する。トラクションの「見せ方の工夫」と「誤解させる加工」（都合のいい期間切り取り・累計グラフでの成長偽装）の線引きを守る
- デザインの作り込みより、ストーリーと数字の整合に時間を使う（シードほどこの傾向が強い）
- 守秘情報・未公開数値が含まれる場合、送付版に含めてよいか確認を促す
