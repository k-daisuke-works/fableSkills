# ペルソナ・カスタマージャーニー設計

施策判断に使えるペルソナと、顧客の行動を可視化するジャーニーマップを作るスキル。

## 大原則

**ペルソナは「誰向けかの判断基準」であって人物紹介ではない。** 施策の取捨選択に使えない項目（好きな映画など）は書かない。また、実データに基づく部分と仮説の部分を必ず区別してマークする。

## 手順

### 1. 材料の確認

- 実データがあるか確認する: 顧客インタビュー、アンケート、アクセス解析、営業の商談メモ、レビュー・問い合わせ履歴
- 何もなければ「仮説ペルソナ」として作り、文書の冒頭に**「未検証の仮説。◯◯で検証すること」**と明記する

### 2. ペルソナ設計

**1製品につき主要ペルソナは1〜2体まで**（3体以上は「全員向け」と同じで、判断基準として機能しない）。

```markdown
# ペルソナ: <呼び名>（主要 / 副次）

## 基本属性（判断に効くものだけ）
役割・職業 / 年齢帯 / 予算決裁権の有無 / ITリテラシー / 情報収集チャネル

## 状況と課題（ここが本体）
- **片付けたい用事 (Job)**: <製品を「雇う」理由。機能でなく達成したい進歩で書く>
- **現在の代替手段**: 今どうやって済ませているか（何もしない、も含む）
- **不満・ペイン**: 代替手段のどこに困っているか（頻度・深刻度付き）
- **切り替えの障害**: 乗り換えをためらう理由（コスト・学習・惰性・不安）

## 購買行動
きっかけ / 比較検討の仕方 / 決裁プロセス（B2Bなら関与者も）/ 決め手になる要素

## 検証状態
[実データ由来] の項目: …　[仮説] の項目: …
```

B2B の場合は「利用者・決裁者・調達/情シス」など役割別に関与者マップを作る（ペルソナ1体では B2B の購買は説明できない）。

### 3. カスタマージャーニーマップ

段階 × 5行のマトリクスで作る:

| | 認知 | 興味・比較 | 購入/導入 | 利用・定着 | 推奨/更新 |
|---|---|---|---|---|---|
| 行動 | | | | | |
| 思考・感情 | | | | | |
| タッチポイント | | | | | |
| 障害・離脱要因 | | | | | |
| 施策機会 | | | | | |

- 感情の谷（不安・面倒のピーク）を特定し、そこへの施策を優先候補にする
- 既存事業なら、各段階の実測データ（CVR・離脱率）を紐付けて「想像のジャーニー」を「実測のジャーニー」に近づける

### 4. 検証の設計

仮説ペルソナのまま終わらせない。最もリスキーな仮説（大抵は「その課題に金を払うほど困っている」）を特定し、検証方法（顧客インタビュー5件、LPテスト、プレオーダー）を提案する。インタビューする場合の質問案（誘導しない・過去の行動を聞く形式）も添える。

## 注意事項

- 属性の作り込み（名前・家族構成・趣味）に時間をかけない。課題と購買行動が本体
- 「みんなに刺さる」ように薄めない。ペルソナ外を捨てる勇気が判断基準としての価値
- 施策の議論で使われて初めて意味を持つ。marketing-strategy / copywriting のインプットになる形で書く
