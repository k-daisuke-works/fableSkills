# 価格戦略設計

「なんとなくの価格」を、価値と検証に基づいた価格戦略に変えるスキル。

## 大原則

**価格はコストからではなく価値から決める。** コストは下限を決めるだけ。上限は「顧客が得る価値」と「代替手段のコスト」が決める。そして価格は一度決めたら終わりではなく、最も強力な利益レバー（価格1%の改善は利益に直結する）として継続的に扱う。

## 手順

### 1. 価格の3つの基準点を出す

- **コスト基準（下限）**: 変動費+固定費配賦から、最低ラインを計算する
- **競合基準（相場）**: 直接競合・代替手段の価格を一覧化する（`market-research` の成果物があれば使う）。顧客が「比較する対象」の価格が実質の相場
- **価値基準（上限）**: 顧客が得る経済価値を数値化する（削減される時間×時給、増える売上、回避されるリスク）。B2Bなら「顧客の得る価値の1/10」が古典的な目安

3点を数直線に並べ、設定可能なレンジを可視化する。

### 2. 価格構造の設計

課金の「軸」を選ぶ（金額より構造が重要）:

- **課金単位**: ユーザー数 / 利用量 / 成果 / 定額 — **顧客の得る価値と一緒に増える軸**を選ぶと、値上げ交渉なしに客単価が育つ
- **プラン構成（松竹梅）**: 3プランが基本。真ん中に主力を置き、上位プランはアンカー(比較対象)として機能させる。プラン間の差は「機能の出し惜しみ」でなく「顧客タイプの違い」で設計する（個人/チーム/企業）
- **フリーミアム**は「無料ユーザーが営業資産になる構造（ネットワーク効果・バイラル）」があるときだけ推奨する。単なる値引きとしてのフリーミアムは CAC を悪化させるだけ
- 心理面: 端数価格、年払い割引（キャッシュフロー改善+解約率低下）、アンカリングの配置

### 3. 影響の試算

価格変更・プラン設計の影響をスクリプトで試算する（`financial-model` と連携）:

- 値上げ: 「離脱率がX%までなら増収」の損益分岐離脱率を計算して提示する（例: 20%値上げ・粗利率80%なら、離脱が約2割以下なら増益）
- プラン分布の仮定を変えたときの ARPU・売上への影響
- 既存顧客の扱い（グランドファザリング=旧価格維持、移行期間）のコスト試算

### 4. 検証の設計

価格の正解は机上では出ない。検証方法を提案する:

- **Van Westendorp（PSM）**: 「高すぎる/安すぎる/高いが検討/お得」の4質問で受容価格帯を推定（10人程度でも傾向は出る）
- 営業での提示テスト（B2B）: 反応を記録して段階的に引き上げる
- LP のプラン表示テスト、事前登録時の価格提示
- 注意: 既存顧客への A/B 価格テストは公平性・炎上リスクがあるため慎重に扱う

### 5. 成果物

①推奨価格・プラン構成とその根拠（3基準点との関係）→ ②プラン比較表（そのままLPに使える粒度）→ ③影響試算 → ④検証計画 → ⑤見直しトリガー（解約率・成約率がどうなったら再検討するか）。

## 注意事項

- 安売りの提案は慎重に。価格を下げるのは一瞬、上げるのは大仕事。迷ったら高めで検証を推す
- 値上げの場合、既存顧客へのコミュニケーション計画（予告期間・理由の説明・旧価格の経過措置）までセットで設計する
- 業界の規制・商慣習（二重価格表示の規制、B2Bの見積り文化）に注意する
