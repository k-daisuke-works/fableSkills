# Material 3 テーマ・デザインシステム

アプリ全体の見た目を一元管理できるテーマ基盤を作るスキル。

## 大原則

**色・文字・形は必ずテーマ経由で参照させる。** 個々の画面に `Color(0xFF...)` や `fontSize = 14.sp` が散らばった時点でデザイン変更が不可能になる。このスキルの仕事は「きれいな色を選ぶ」ことではなく「一箇所直せば全部変わる構造」を作ること。

## 手順

### 1. 現状確認

- 既存の `ui/theme/`（Color.kt / Theme.kt / Type.kt）とブランド指定（ロゴ・既存サイト・指定色）を確認する
- 画面コードを grep してテーマを迂回したリテラル色・サイズの分布を把握する（改善対象リスト）

### 2. カラースキームの構築

- ブランドのシード色から Material 3 のトーンパレットを組み立てる（primary / secondary / tertiary / error + それぞれの container / on- 色)。手作業で全スロットを決めず、シード色ベースの生成を基本にし、ブランド上譲れない色だけ上書きする
- **ライト・ダークを最初からペアで定義する**。ダークは「黒背景に同じ色」ではなく、彩度を落としたトーン（Material 3 の流儀）で
- **ダイナミックカラー**（Android 12+、壁紙由来）: 対応するか方針を確認する。ブランド色が重要なアプリでは無効が正解のこともある — トレードオフを説明して選ばせる
- コントラスト検証: 主要な組み合わせ（onPrimary/primary, onSurface/surface 等）が WCAG AA（4.5:1）を満たすか計算し、結果を表で示す

### 3. タイポグラフィと形状

- `Type.kt` で Material 3 のタイプスケール（display〜label）にアプリのフォントを割り当てる。カスタムフォントはライセンス確認を促す
- 日本語では行間（lineHeight）を英語デフォルトより広めに取ると読みやすい
- Shape（角丸の段階）を定義し、カード・ボタン・シートで使い分けを統一する

### 4. テーマを超える共通トークン

Material のスロットで足りないもの（成功色・ブランド固有色・余白の段階）は、`LocalXxx` の CompositionLocal か拡張プロパティでアプリ独自トークンとして定義し、やはり一元管理する。余白は 4dp グリッド（4/8/12/16/24/32）の段階で。

### 5. 適用と移行

- 新テーマを適用し、**全画面のスクリーンショット確認**（またはPreview一覧）でライト/ダーク両方の崩れを見る
- 既存のリテラル色・サイズは一括置換せず、意味を判断しながらトークンに割り当てる（同じ #666 でも「無効状態」と「区切り線」は別トークン）
- ステータスバー・ナビゲーションバーの色/アイコン明暗（edge-to-edge 対応含む）まで揃える

## 成果物

- `ui/theme/` 一式（Color / Theme / Type / Shape / 独自トークン）
- ライト・ダークのカラースキーム一覧表（コントラスト比付き）
- 使い方ガイド（「テキストの色に迷ったら」等の早見表。プロジェクトの CLAUDE.md か docs/ に置く）

## 注意事項

- デザイナー・既存デザインシステムがいる/ある場合はそちらが正。勝手にMaterialのデフォルトへJ正規化しない
- ダークテーマは後回しにさせない（後付けは全画面の再確認になる。最初からペアで作る方が総コストが低い）
- OLED向け純黒背景の希望など、Material の標準から外れる要望は実装可能だが保守コストを説明する
