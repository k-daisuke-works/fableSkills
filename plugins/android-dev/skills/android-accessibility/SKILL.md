# Androidアクセシビリティ

スクリーンリーダー・拡大表示・キーボードでも使えるアプリにするスキル。

## 大原則

**アクセシビリティは追加機能ではなく品質。** 対応は「TalkBackで全部読み上げる」ことではなく「TalkBackだけで**タスクを完了できる**」こと。読み上げ順・操作可能性・状態の伝達をユーザーのタスク単位で確認する。

## レビュー・実装の観点

### セマンティクス（Compose）

- 画像・アイコンボタン: 意味があるなら `contentDescription` を設定、**装飾なら明示的に `null`**（空文字や「画像」は逆に害）
- テキストで意味が完結する要素に冗長な description を重ねない
- カスタムコンポーネント（独自のトグル・スライダー等）は `Modifier.semantics` で役割 (`role`)・状態 (`stateDescription`, `toggleableState`)・カスタムアクションを宣言する
- 複合要素（カード内のタイトル+説明+ボタン）は `semantics(mergeDescendants = true)` で1タップ対象として読み上げをまとめ、内部の操作はカスタムアクション化を検討する
- 動的な変化（エラー出現・完了）を伝える必要があれば `liveRegion` を設定する

### 操作性

- **タッチターゲット最小 48dp**（視覚サイズが小さくても `minimumInteractiveComponentSize` やパディングで確保）
- キーボード/スイッチアクセス: フォーカス順序が視覚順と一致するか、フォーカス表示が見えるか
- 長押し・スワイプ・ドラッグだけの操作に代替手段（メニュー・ボタン）を用意する
- 時間制限のある操作（自動で消えるスナックバー上の重要アクション等）に猶予・代替を用意する

### 表示

- コントラスト: テキスト 4.5:1（大テキスト 3:1）。`material-theming` のテーマ検証と連携
- **フォントスケール 2.0 で崩れない**: sp と dp の使い分け（文字は sp、アイコンサイズ等は要件次第）、固定高さのコンテナに文字を入れない、はみ出しは折り返し・スクロールで受ける
- 色だけで情報を伝えない（エラー=赤だけでなくアイコン+文言）
- アニメーション: `Settings.Global.ANIMATOR_DURATION_SCALE` 尊重、点滅・激しい動きの抑制設定

## 手順

1. **対象の確認**: アプリ全体か特定画面か。主要タスク（このアプリで一番大事な操作フロー）を特定する
2. **静的チェック**: コードを走査して上記観点の違反を洗い出す（contentDescription 欠落、48dp未満、sp/dp誤用、色のみの伝達）
3. **動的チェック**（環境があれば）: TalkBack を有効化して主要タスクを最後まで実行 / フォントスケール最大で全画面確認 / Accessibility Scanner の実行
4. **修正**: 影響の大きい順（操作不能 > 情報欠落 > 冗長・不快 > 見た目）に適用する
5. **報告**: 修正一覧と、確認できなかった項目（実機が必要なもの）の手動テスト手順を渡す

## テストへの組み込み

- Compose UI テストでセマンティクスを検証できる（`onNodeWithContentDescription` 等で書かれたテストはアクセシビリティの回帰検知を兼ねる）
- CI に Accessibility チェック（Lint の a11y ルール有効化）を足すことを提案する

## 注意事項

- 読み上げ文言は日本語として自然に（「ボタン、送信」と二重に役割を言わない — role は自動で付く）
- 「アクセシビリティ対応版の別画面」を作る提案はしない（本画面を直すのが原則）
- 公共系・大企業案件では準拠基準（WCAG 2.1 AA / JIS X 8341-3）の指定を確認し、基準への適合表を成果物に含める
