# レベルデザイン

個々のレベル/ステージの設計と、ゲーム全体の難易度カーブの設計・レビューを行うスキル。

## 手順

### 1. 前提の把握

- GDD やコンセプトシートがあれば読み、コアメカニクスと操作系を把握する
- 既存のレベルデータ（Tiled の JSON、CSV、シーンファイル、ハードコードされた配列など）があれば形式を把握し、**同じ形式で**成果物を出す
- どちらもない場合は、コアメカニクス（プレイヤーは何ができるか）だけ確認してから進める

### 2. 全体構成（マクロ）の設計

レベル一覧を設計する場合は「教える → 試す → 応用させる → 総合試験」のリズムで組む:

1. **導入**: 新メカニクスを安全な環境で1つだけ教える（失敗してもペナルティ最小）
2. **練習**: 教えたメカニクスを少し難しい状況で使わせる
3. **応用**: 既存メカニクスとの組み合わせを要求する
4. **試験**: 複合状況（ボス・タイムアタック等）で習熟を確認する

各レベルに「このレベルで教える/試すこと」を1つ割り当てた表を作る。教えることが1つもないレベルは水増しなので削るか統合を提案する。

### 3. 個別レベル（ミクロ）の設計

各レベルはビート（体験の起伏）で設計する:

```markdown
## Level <N>: <名前>

**目的**: このレベルで教える/試すこと
**想定クリア時間**: X分
**ビート構成**:
1. [緊張度: 低] オープニング — 安全地帯。今回のテーマを視覚的に提示
2. [緊張度: 中] チャレンジ1 — ...
3. [緊張度: 低] 休憩 — 回復・報酬・寄り道
4. [緊張度: 高] クライマックス — ...
5. [緊張度: 低] 解決 — ゴール前の達成感の演出

**リスクとリワードの配置**: 寄り道報酬の場所と、そのために冒すリスク
**失敗時の復帰**: チェックポイント位置、リトライで失うもの
```

レイアウトが必要な場合は ASCII / テキストグリッドで俯瞰図を描く。既存のレベルデータ形式があるなら実データも生成する。

### 4. 難易度カーブのレビュー

既存レベルのレビューを頼まれたら:

- **スパイク検出**: 前のレベルとの難易度差が大きすぎる箇所（新要素2つ以上の同時導入、要求精度の急上昇）
- **中だるみ検出**: 3レベル以上連続で新しい要素・状況がない区間
- **理不尽検出**: 初見では回避不可能な罠（学習ではなく暗記を要求するもの）。意図的な場合を除き指摘する
- **導線**: プレイヤーが進むべき方向に迷う箇所（視線誘導・ライティング・配置で解決策を提案）
- 数値データがあれば `/game-balance` の手法（シミュレーション）で検証する

### 5. 検証

- レベルデータを生成した場合、ロードして壊れないか確認できる手段（テスト・バリデータ）があれば実行する
- クリア不能な構成（必須アイテムが到達不能、ジャンプ距離が物理的に届かない等）を机上でチェックする

## 注意事項

- 難易度は「敵を固くする」以外の軸を優先して提案する（状況の複雑化、判断時間の短縮、複数目標の同時要求）
- チュートリアルはテキストで説明するのではなく、状況で教える設計を第一候補にする
- ユーザーのゲームのジャンル慣習を尊重する（メトロイドヴァニアの探索リズムと、ステージクリア型のリズムは別物）
