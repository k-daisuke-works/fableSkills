# ゲームナラティブ設計・執筆

世界観・キャラクター・シナリオ・ゲーム内テキストを、**ゲームプレイと噛み合う形で**設計・執筆するスキル。

## 大原則

ゲームのナラティブは小説ではない。**プレイヤーの行動が物語の一部**になるよう、メカニクスと矛盾しない設定を作る（例: 「一刻を争う」シナリオで釣りミニゲームが並ぶと白ける — 許すなら理由を用意する）。

## 手順

### 1. 前提の把握

- GDD・コンセプトシートがあれば読み、コアループ・トーン・ターゲット層を把握する
- 既存の設定資料・テキストデータがあれば読み、文体・固有名詞・敬語規則を把握して**必ず踏襲する**
- 新規なら、トーン（シリアス⇔コミカル、重厚⇔ライト）とテキスト量の想定（フレーバーのみ / カットシーンあり / フルボイス級）を確認する

### 2. 世界観設計

`docs/narrative/world.md` に、**ゲームに現れる範囲を優先して**書く:

- **中心の緊張**: この世界の根本的な対立・問題を1文で（すべての設定はここから派生させる）
- **プレイヤーの立ち位置**: プレイヤーは何者で、なぜ冒険（=コアループの行動）をするのか
- **ビジュアル・音への示唆**: 設定がアートに落ちるフック（技術水準、文化、色彩の傾向）
- 年表・地理は「ゲームに登場する分+背景1層」まで。使われない設定の肥大化は避ける

### 3. キャラクター設計

各キャラは以下のテンプレートで。**「設定」より「機能」から作る**:

```markdown
## <名前>
**ゲーム内機能**: プレイヤーにとって何者か（導き手/壁/商人/ライバル）
**欲求と矛盾**: 何を求め、何がそれを妨げているか（キャラの魅力の核）
**声**: 一人称・口調・口癖・言わないこと。セリフサンプル3行
**アーク**: 物語を通じてどう変わるか（変わらないならそれが意味を持つか）
```

### 4. シナリオ・クエスト構造

- 全体は三幕またはゲームの章構成に合わせたビート表で設計する（各ビート = 状況変化1つ）
- **各ビートで「プレイヤーがすること」を必ず併記する**。読む/見るだけのビートが3つ以上続いたら設計を見直す
- 分岐がある場合は分岐図を作り、フラグ管理表（フラグ名・立つ条件・参照箇所）を添える。合流の質（分岐が無意味に見えないか）を確認する

### 5. テキスト執筆

- **UIテキスト・システムメッセージ**: 簡潔・一貫・機械的に正確（用語集を作り表記を統一）
- **セリフ**: キャラの「声」設定に従う。読み上げて不自然な行は書き直す。1吹き出し・1ウィンドウの文字数制限を確認してから書く
- **フレーバーテキスト**: 世界の「中心の緊張」を別角度から照らす小話に。単なる説明文にしない
- テキストはコード埋め込みではなくデータファイル（JSON/CSV/gettext等）に置くことを提案する（`/game-localization` の前提になる）

### 6. 一貫性チェック（レビューモード）

既存テキストのレビューでは: 固有名詞の表記ゆれ、キャラの口調ブレ、時系列矛盾、メカニクスとの矛盾（「二度と会えない」と言ったNPCが店にいる等）を洗い出して一覧にする。

## 注意事項

- 既存作品の設定・キャラクターの模倣はしない。「〇〇風」の依頼は構造（関係性・トーン）を参考にし、表層（名前・見た目・固有の設定）はオリジナルにする
- 対象年齢レーティング（CERO等）を意識し、想定を超える表現はユーザーに確認する
- 用語集（固有名詞・訳語・表記規則）は `docs/narrative/glossary.md` に必ず育てる。全テキスト作業の前にこれを読む
