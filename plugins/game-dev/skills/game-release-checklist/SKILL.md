# ゲームリリース準備

リリース前の最終チェックと公開準備を、プラットフォームの要件に沿って進めるスキル。

## 手順

### 1. リリース情報の確認

- 対象プラットフォーム（Steam / itch.io / Google Play / App Store / Web / コンソール）
- 価格形態、対象地域・言語、リリース日程
- 現在の状態（開発完了度、既知バグ、ストアページの有無）

### 2. 共通チェックリストの実施

コード・ビルド・データを確認できるものは実際に確認し、できないものはチェックリストとして渡す:

**ビルド・起動**
- [ ] リリースビルドが**クリーンな環境**（開発機以外）で起動するか — 開発機にしかないランタイム・パス依存が最頻出の初日バグ
- [ ] デバッグ機能の無効化: チートキー、デバッグ表示、開発者コンソール、ログの過剰出力
- [ ] ビルドサイズと初回ロード時間が想定内か
- [ ] バージョン番号がゲーム内で確認できるか（不具合報告の照合に必須）

**データ・進行**
- [ ] 新規開始→クリアまでの通しプレイが（自動化含め）最終ビルドで確認済みか
- [ ] 旧バージョンのセーブデータの扱い（互換 / 変換 / 切り捨ての明示）
- [ ] セーブデータ破損時の挙動（クラッシュループしないか）

**法務・表記**
- [ ] 使用アセット・ライブラリ・フォントのライセンス一覧と、要求されるクレジット表記
- [ ] 個人情報・テレメトリを収集する場合のプライバシーポリシー
- [ ] 必要なレーティング取得（IARC / CERO 等、プラットフォームに応じて）

**アクセシビリティ・品質**
- [ ] 音量設定（マスター/BGM/SE 個別）、画面効果（シェイク・フラッシュ）のオフ設定
- [ ] キーコンフィグまたは主要デバイスでの操作確認
- [ ] 最低スペック環境での動作確認

### 3. プラットフォーム別の確認

対象プラットフォームの要件を確認する。**要件は頻繁に変わるため、最新の公式ドキュメントを WebSearch/WebFetch で確認してから**チェックリスト化する。代表的な観点:

- **Steam**: ストアページ素材一式（カプセル画像各サイズ・スクリーンショット・トレーラー）、Steamworks 設定（実績・クラウドセーブ・Deck 互換）、ビルドのデポ構成、審査リードタイム
- **itch.io**: ページ作成、Web ビルドなら iframe サイズ・フルスクリーン動作、価格/寄付設定
- **モバイル**: 署名・証明書、ストア審査ガイドライン（特にガチャ確率表示・子ども向け判定）、ターゲット API レベル、スクリーンショット規格
- **Web**: ホスティング、モバイルブラウザ動作、音声の自動再生制限（ユーザー操作後に AudioContext を開始しているか）

### 4. ストア文言・素材の支援

依頼があれば、ストア説明文（短文・長文）、特徴リスト、タグ選定、プレスキット（factsheet / スクリーンショット構成案）を作成する。説明文は「ジャンル+フック+コアループ」を最初の2文に入れる。

### 5. リリース後の初動準備

- 不具合報告の受け口（フォーム / Discord / ストアフォーラム）と、報告テンプレート（バージョン・環境・再現手順）
- ホットフィックスの手順確認（ビルド→審査→配信のリードタイム把握）
- 初週にウォッチする指標（クラッシュ率、レビュー、離脱ポイント）の一覧

## 注意事項

- チェック結果は「確認済み（証拠付き）/ 未確認 / 該当なし」を明確に分ける。確認していない項目を済みにしない
- リリース直前の「ついでの修正」はリスクが利益を上回ることを警告する（変更したらチェックのやり直しが必要）
- ストア規約・審査基準は変動が激しい。このスキルの記述より公式ドキュメントを常に優先する
