# ゲームフィール（手触り）改善

「なんか気持ちよくない」を具体的な原因に分解し、コードで改善するスキル。

## 手順

### 1. 症状の分解

「気持ちよくない」は必ず下位の問題に分解してから直す。ユーザーの訴えとコードから該当領域を特定する:

- **入力への応答が鈍い** → 入力遅延・受付の問題
- **動きが硬い/滑る** → 移動パラメータ・補間の問題
- **攻撃が当たった気がしない** → ヒットフィードバックの問題
- **画面が死んでいる** → 環境反応・アニメーションの問題

### 2. 領域別チェックリスト

**入力応答**
- [ ] 入力から画面反応まで 100ms 以内か（理想は 50ms 以内。入力ポーリングのタイミング、イベントのフレーム跨ぎを確認）
- [ ] ジャンプに猶予があるか: **コヨーテタイム**（崖から離れて 4〜6 フレームはジャンプ可）と**入力バッファ**（着地の 4〜6 フレーム前の入力を保持）
- [ ] ボタン長押しで挙動が変わる場合、短押しの判定が渋くないか
- [ ] 連打・同時押しで入力が食われないか

**移動の手触り**
- [ ] 加速・減速が意図的に設計されているか（即最高速は硬く、慣性過多は滑る。ジャンルの慣習に合わせる）
- [ ] ジャンプ曲線: 上昇より落下を速く（重力を落下時 1.5〜2 倍）すると操作感が締まる。頂点で僅かな滞空を入れると制御感が出る
- [ ] 可変ジャンプ（ボタンを離すと上昇打ち切り）があるか
- [ ] 壁・段差の角に引っかからないか（コーナーの許し: 角を丸める・自動で押し出す）

**ヒットフィードバック（打撃の三点セット+α）**
- [ ] **ヒットストップ**: 命中時に 2〜6 フレーム両者を停止。強攻撃ほど長く
- [ ] **画面シェイク**: 減衰付きランダムオフセット。強さは 2〜8px、時間 0.1〜0.3 秒。多用による酔いに注意（設定でオフ可能に）
- [ ] **ヒットフラッシュ**: 被弾側を 1〜2 フレーム白点滅
- [ ] パーティクル・ノックバック・効果音が命中の強さに比例しているか
- [ ] ダメージ数字等、結果の可視化があるか

**環境の生命感**
- [ ] 待機アニメーション（呼吸程度でよい）があるか
- [ ] 移動・着地に伴う副次表現（土煙、足音、スカッシュ&ストレッチ）があるか
- [ ] UI の状態変化がスナップせず、短い（0.1〜0.2秒）イージングで動くか

### 3. 実装の作法

- 効果はすべて**強度パラメータ付きの汎用関数**として実装する（`shake(intensity, duration)`、`hitstop(frames)`）。個別実装をばら撒かない
- 一度に1種類ずつ入れて確認する。全部同時に入れると過剰演出（うるさい画面）に気づけない
- 「引き算」も提案する: エフェクト過多で重要な情報（敵の攻撃予兆）が埋もれていたら削る
- 数値（フレーム数・強度）は CONFIG に集約し、ユーザーが自分で微調整できるようにする

### 4. 検証

- 実行環境があれば動かして before/after を確認する
- ヒットストップ・シェイクはゲーム全体の時間管理（ポーズ・スロー）と干渉しやすい。ポーズ中の発動、多重発動、演出中の入力バッファの挙動を確認する

## 注意事項

- ジュースはコアの面白さを置き換えない。コアループがつまらない場合は正直にそう伝える（`/game-prototype` の検証に戻る）
- アクセシビリティ: シェイク・フラッシュは酔い・光過敏の原因になる。強度設定/オフ手段の実装を必ず提案する
- ジャンルの文脈を守る（精密プラットフォーマーに過剰な慣性、パズルゲームに長いヒットストップは逆効果）
