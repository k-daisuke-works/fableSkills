# ゲーム企画書・コンセプトシート作成

アイデアの断片から、チームや意思決定者に見せられる1〜2ページのコンセプトシートを作るスキル。

## 手順

### 1. 素材の収集

ユーザーの依頼から以下を拾う。**足りない項目は勝手に埋めず、最初に一度だけまとめて質問する**（ターゲット・プラットフォーム・規模は特に重要）:

- ジャンル / 参考にしたいゲーム
- ターゲット層（年齢・ゲーム経験・プレイ時間帯）
- プラットフォーム（PC / モバイル / コンソール / Web）
- 開発規模（個人 / 小規模チーム / 商業）と期間
- マネタイズ（買い切り / F2P / 広告 / なし）

ユーザーが「お任せ」と言った場合のみ、妥当なデフォルトを選んで明記する。

### 2. コンセプトの核を1文にする

最初に **「〇〇が、△△することで、□□を体験するゲーム」** の形式で核を1文に凝縮する。この1文で面白さが伝わらない場合は構成要素を変えて3案作り、ユーザーに選ばせる。

### 3. コンセプトシートの作成

以下の構成で `docs/concept.md`（またはユーザー指定の場所）に書く:

```markdown
# <タイトル（仮）>

## コンセプト
<核となる1文>

## エレベーターピッチ
「<参考ゲームA> × <参考ゲームB>」のような1段落の説明。
何が新しいのか・なぜ面白いのかを含める。

## ターゲットとプラットフォーム
| 項目 | 内容 |
|---|---|
| ターゲット | |
| プラットフォーム | |
| プレイセッション長 | |
| 価格・マネタイズ | |

## コアループ
プレイヤーが繰り返す行動のループを3〜5ステップで。
例: 探索 → 素材入手 → 装備強化 → より深く探索

## 差別化ポイント
類似ゲームと比較して何が違うのか、3点まで。

## 最初の5分
プレイヤーが起動してから最初の5分で何を体験するか。
（ここが曖昧な企画は大抵コアが弱い）

## リスクと未解決の問題
技術・デザイン・スコープ上の懸念を正直に列挙。

## スコープ感
MVP（最小の遊べる形）に必要な要素と、あれば嬉しい要素を分けて列挙。
```

### 4. セルフレビュー

書き上げたら以下を自問し、弱い箇所はユーザーに正直に指摘する:

- コアループは**それ単体で**面白いか（メタ進行やストーリーに依存していないか）
- 「最初の5分」でコンセプトの面白さが伝わるか
- MVP のスコープは開発規模に対して現実的か（個人開発で「オープンワールドMMO」は破綻）
- 差別化ポイントは実装コストに見合うか

## 注意事項

- 企画の良し悪しについてお世辞を言わない。スコープ過大・コア不明瞭などの問題は明確に伝える
- 複数案を求められたら、方向性の異なる案を出す（同じ案のバリエーション3つは無意味）
- 次のステップとして `/game-design-doc`（詳細設計）や `/game-prototype`（動くもの作り）につなげられることを伝える
