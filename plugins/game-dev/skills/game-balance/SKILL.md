# ゲームバランス設計・検証

数値バランスを「感覚」ではなく「目標値とシミュレーション」で設計・検証するスキル。

## 大原則

**体験目標から逆算する。** 「HP をいくつにするか」から始めず、「雑魚戦は10秒・ボス戦は3分で終わってほしい」「レベル差3までは勝負になってほしい」という体験目標を先に決め、そこから数値を導く。

## 手順

### 1. 現状把握と目標設定

- 既存の数値データ（ステータス表、計算式のコード、CSV/JSON）を読み込む。計算式はコードから正確に拾う（ドキュメントは古いことが多い）
- ユーザーと体験目標を確認する。最低限決めるもの:
  - **TTK/戦闘時間**: 標準的な戦闘が何秒/何ターンで終わるべきか
  - **成長実感の周期**: プレイヤーが「強くなった」と感じる間隔（例: 30分ごと）
  - **許容されるビルド幅**: 最強一択にせず、何通りの有効な選択肢を残したいか

### 2. 数値骨格の設計（新規設計の場合）

- **基準ユニットを1つ決める**（Lv1 プレイヤー vs 標準的な雑魚）。すべての数値はここからの相対値で作る
- 成長曲線は用途で使い分ける:
  - 線形: 分かりやすいが後半に成長実感が薄れる
  - 指数(緩): 成長実感が持続するがインフレしやすい。係数 1.05〜1.15/Lv 程度から始める
  - ロジスティック: 上限に収束。対人バランスを守りたいステータス向け
- ダメージ式は「減算式（攻-防）」「除算式（攻×攻/(攻+防)）」等の特性差を理解して選ぶ。減算式は防御の閾値超えで急変するため、その崖が意図的か確認する
- 数値表はコードにハードコードせず、データファイル（CSV/JSON）に出すことを提案する

### 3. シミュレーションによる検証

**ここがこのスキルの核。** 数値を目視で眺めて「良さそう」で終わらせず、スクリプトで検証する:

1. ゲームの計算式を忠実に再現したシミュレータ（Python または JS）をスクラッチパッドに書く
2. 検証したい問いをコード化する:
   - 全レベル帯 × 全敵種の戦闘時間マトリクスを出し、目標帯から外れるセルを列挙
   - 全武器/ビルドの DPS・生存時間を計算し、支配的選択肢（他を完全に上回る）と死に選択肢を検出
   - 乱数が絡む場合はモンテカルロ（1万回試行）で分布を出す。平均だけでなく分位点（下位5%の不運なケース）を見る
3. 結果を表・必要ならグラフで示し、逸脱箇所と修正案（どの数値をいくつに変えるか）をセットで報告する
4. 修正案を適用したら**再シミュレーションして確認**する

### 4. 調整の作法

- 一度に動かす変数は最小限にする（複数同時に変えると因果が分からなくなる）
- ナーフよりバフを優先検討する（使用感を壊されたプレイヤーの不満はバフの喜びより大きい）。ただしインフレの天井も考慮
- 変更は変更履歴（何を・いくつ→いくつ・なぜ）として残す

## 注意事項

- シミュレータはゲーム本体の計算式と乖離すると無意味。式をコードから写した場合は該当箇所（`file:line`）を報告に明記する
- 「数学的に均衡=面白い」ではない。あえて強い選択肢・ロマン枠を残す判断はユーザーに委ね、データだけ提供する
- PvP と PvE ではバランスの厳しさの基準が全く違う。どちらの文脈か常に確認する
