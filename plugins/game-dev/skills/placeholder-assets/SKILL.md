# プレースホルダー素材生成

アートワーカーがいない・まだいない段階で、ゲームを見られる状態にする仮素材を生成するスキル。「灰色の四角」より一段上の、**ゲームの雰囲気が伝わる**プレースホルダーを作る。

## 原則

- **識別性 > 美しさ**: プレイヤー・敵・アイテム・地形が一瞬で見分けられること。色相・シルエット・サイズを機能ごとに割り当てる
- **差し替え可能に**: 本番素材への差し替えを想定し、サイズ規格（16/32/64px 等）とファイル命名をユーザーのプロジェクト規約か一般慣習に合わせる
- **プロジェクトのパイプラインに合わせる**: 既存のアセットディレクトリ・ローダーがあればその形式（PNG/SVG/スプライトシート）で出力する

## 素材タイプ別の作り方

### スプライト（SVG）

SVG をコードで書く。単純図形の組み合わせでキャラクター性を出す:

- **シルエット重視**: プレイヤーは縦長、敵は角ばり、アイテムは小さく丸く…と機能で形を変える
- 各機能に固定の色相を割り当てる（プレイヤー=青系、敵=赤系、回収物=黄系、危険地形=橙系、等）。色は3〜4色/スプライトまで
- 向きのあるキャラには向きが分かる要素（目・くちばし状の突起）を入れる
- アニメーションが必要なら2〜4フレームの差分（歩行=足の開閉、待機=1px上下）を作る
- PNG が必要な場合: `rsvg-convert` / `resvg` / ImageMagick が使えるか確認して変換。なければ SVG のまま使える方法を提案する

### プログラム描画（エンジン内蔵図形）

プロトタイプ段階ならファイルを作らず、Canvas/エンジンの描画 API で直接描く関数を書く方が反復が速い。`drawPlayer(ctx, x, y, state)` のような関数群として提供する。

### タイルセット / 背景

- 地形タイルは「歩ける/歩けない/危険」が色で即判別できるように
- 単色ベタではなく、僅かなノイズや枠線を入れる（動いたときに移動が知覚できないため）
- Tiled 等を使うプロジェクトならタイルシート画像+規格（タイルサイズ・マージン）で出力する

### 効果音（Web Audio / jsfxr系）

ブラウザゲームなら Web Audio API で合成する関数を書く:

- ジャンプ=矩形波の上昇スイープ、コイン=高音の2音、ダメージ=ノイズ+下降、爆発=ローパスノイズ減衰
- 1音1関数で提供し、パラメータ（周波数・長さ）を引数化する
- ファイルが必要な環境なら、生成スクリプト（Python + numpy/wave 等）で WAV を書き出す

### パーティクル・エフェクト

ヒット・爆発・回収などのエフェクトは素材ではなくコードで:「N個の矩形が放射状に飛んで減衰」程度の汎用パーティクル関数を1つ提供し、色・数・速度のプリセットで使い分ける。

## 手順

1. 必要な素材の一覧をゲームの内容から洗い出し、機能→色相/シルエットの割り当て表を先に作ってユーザーに見せる
2. 割り当てに沿って一括生成する
3. 可能なら全素材を1画面に並べたプレビュー（HTML）を作り、識別性を目視確認する
4. ゲームへの組み込み方法（ローダーへの登録・パス）まで面倒を見る

## 注意事項

- 既存の本番素材があるスロットを勝手にプレースホルダーで上書きしない
- 他ゲームのキャラクターや既存 IP に似せた素材は作らない（仮でも著作権リスクになる）
- フリー素材サイトの利用を提案する場合はライセンス（CC0 / CC-BY / 商用可否）の確認を必ず添える
