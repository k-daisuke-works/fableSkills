1基本情報

ゲームの外形。実装者が技術選定とスコープ感を掴むための土台です。

雰囲気・操作感の参考。「〇〇の△△の部分」まで書くと伝わります。

2コンセプト

このゲームの「面白さの核」。実装者は迷ったとき、常にここに立ち返って判断します。

形式: 「〇〇（プレイヤー）が、△△（行動）することで、□□（体験・感情）を味わうゲーム」

プレイ中のベストな3秒間を具体的に。実装者はこの瞬間の手触りを最優先で作り込みます。

3コアループ

プレイヤーが繰り返す行動のサイクル。ここが曖昧だとゲームになりません。

1行1ステップで。最後のステップが最初に戻る流れになっているか確認。

繰り返しても飽きない理由。プレイヤースキル（操作・判断）とゲーム内成長のどちらか、または両方。

4操作

入力と操作の割り当て。

「入力 = 動作」の形式で1行ずつ。空欄ならジャンル標準の操作を実装者が設定します。

5主要メカニクス

ゲームを構成するルールを1つずつ。数値は仮でよいので必ず入れるのがコツです（「速い」ではなく「移動速度 300px/秒」）。最低1つ、コアループに登場する要素はすべて書いてください。

6ゲームフローと画面

起動からゲームオーバーまでの流れと、画面に常時表示する情報。

空欄なら標準構成（タイトル → プレイ → ゲームオーバー → リトライ）になります。

7勝敗条件と進行

「いつ勝ち、いつ負け、何が増えていくか」。

9ビジュアルとサウンド

アートの方向性。プログラム描画・図形ベースの仮素材でも十分遊べるゲームになります。

10技術要件

実装形式の指定。迷ったら「単一HTMLファイル」が最も確実に動きます。

11スコープ

「どこまで作れば完成か」の線引き。実装者の暴走（作り込みすぎ・未完成）を防ぐ最重要セクションです。

1行1機能で。ここに書いたものがすべて動いて初めて「完成」です。
