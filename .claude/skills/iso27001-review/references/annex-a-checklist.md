# ISO/IEC 27001:2022 附属書A — コードレビュー用チェックリスト

コードから観察可能な管理策のみを抜粋し、具体的な確認項目にマッピングしたもの。
各項目は「何を確認するか」→「典型的な逸脱例」の順で記載。

## 1. アクセス制御・認証 (A.5.15 アクセス制御, A.5.16 識別情報の管理, A.5.18 アクセス権, A.8.2 特権的アクセス権, A.8.3 情報へのアクセス制限, A.8.4 ソースコードへのアクセス, A.8.5 セキュリティに配慮した認証)

確認項目:
- [ ] すべての API エンドポイント / ルートに認証・認可チェックがあるか（デフォルト拒否になっているか）
- [ ] 認可は役割・属性ベースで一元化されているか（各所に散在した if 文でないか）
- [ ] 管理者権限の付与・使用箇所が限定され、監査ログの対象になっているか
- [ ] セッション管理: タイムアウト、ログアウト時の無効化、セッション固定攻撃対策があるか
- [ ] パスワード保存はソルト付きの適応型ハッシュ（bcrypt / scrypt / argon2）か
- [ ] 多要素認証や失敗回数制限（レートリミット・ロックアウト）の仕組みがあるか

典型的な逸脱:
- 認証ミドルウェアの適用漏れがあるルート
- `role == "admin"` のようなハードコードされた文字列比較の散在
- MD5 / SHA-1 / 平文でのパスワード保存
- IDOR（他人のリソース ID を指定するとアクセスできる）

## 2. 秘密情報・認証情報の管理 (A.5.17 認証情報)

確認項目:
- [ ] API キー・パスワード・トークン・秘密鍵がソースコードや設定ファイルにハードコードされていないか
- [ ] git 履歴に秘密情報が残っていないか（怪しい場合は `git log -p` を該当ファイルに絞って確認）
- [ ] `.env` 等の秘密情報ファイルが `.gitignore` に含まれているか
- [ ] 秘密情報はシークレット管理サービスまたは環境変数経由で注入されているか
- [ ] ログ・エラーメッセージ・例外に秘密情報が出力されていないか

典型的な逸脱:
- `password = "..."`, `api_key = "sk-..."` のリテラル
- `.env` がコミット済み
- デバッグログにリクエストヘッダ（Authorization 含む）を丸ごと出力

## 3. 暗号化 (A.8.24 暗号の利用)

確認項目:
- [ ] 通信は TLS 強制か（`http://` のハードコード、`verify=False` / `InsecureSkipVerify` 等の検証無効化がないか）
- [ ] 機微データの保存時暗号化が行われているか（またはインフラ側で担保されている前提が明記されているか)
- [ ] 使用アルゴリズムが現行推奨か（AES-GCM, ChaCha20-Poly1305 等。DES / RC4 / ECB モード / MD5 / SHA-1 は不可）
- [ ] 鍵・IV・nonce の生成に暗号論的乱数（CSPRNG）を使っているか（`Math.random` / `rand()` 不可）
- [ ] 鍵のローテーションや管理方法がコード上で破綻していないか（鍵のハードコード不可）

## 4. ログ取得と監視 (A.8.15 ログ取得, A.8.16 監視活動)

確認項目:
- [ ] 認証イベント（成功・失敗）、権限変更、機微データへのアクセスがログに記録されるか
- [ ] ログに個人情報・秘密情報が平文で含まれていないか（マスキングの有無）
- [ ] ログにタイムスタンプ・アクター（誰が）・対象（何に）が含まれるか
- [ ] ログの改ざん・削除がアプリケーションコードから容易にできない構成か
- [ ] エラーの握りつぶし（catch して無視）で監視から漏れるパスがないか

## 5. セキュア開発 (A.8.25 セキュリティに配慮した開発のライフサイクル, A.8.26 アプリケーションのセキュリティ要求事項, A.8.27 セキュリティに配慮したシステムアーキテクチャ及び構築の原則, A.8.28 セキュリティに配慮したコーディング, A.8.29 開発及び受入れにおけるセキュリティ試験, A.8.31 開発環境、試験環境及び本番環境の分離)

確認項目:
- [ ] 入力検証: SQL インジェクション（プレースホルダ使用か）、XSS（出力エスケープか）、パストラバーサル、コマンドインジェクション、SSRF 対策
- [ ] デシリアライズ・eval・動的コード実行に外部入力が渡っていないか
- [ ] エラーハンドリング: スタックトレースや内部情報を外部レスポンスに出していないか
- [ ] セキュリティ関連のテスト（認可テスト、バリデーションテスト）が存在するか
- [ ] 本番・開発環境の分離: 本番設定にデバッグモード有効化・テスト用バックドア・ダミー認証が残っていないか
- [ ] CI にセキュリティチェック（lint, SAST, secret scanning, 依存関係監査）が組み込まれているか

## 6. データ保護 (A.5.33 記録の保護, A.5.34 プライバシー及び個人情報保護, A.8.10 情報の削除, A.8.11 データマスキング, A.8.12 データ漏えい防止)

確認項目:
- [ ] 個人情報（PII）の取り扱い箇所が特定でき、必要最小限か
- [ ] 表示・エクスポート・ログでの PII マスキングがあるか
- [ ] データ削除機能が論理削除だけでなく要件に応じた物理削除に対応しているか（保持期間の考慮）
- [ ] テストデータ・フィクスチャに本番由来の実データが含まれていないか

## 7. バックアップ・可用性 (A.8.13 情報のバックアップ, A.8.14 情報処理施設・設備の冗長性)

確認項目:
- [ ] マイグレーションや一括更新処理に、失敗時のロールバック手段があるか
- [ ] 破壊的操作（DROP, 一括 DELETE, 上書き）に確認・保護があるか
- [ ] バックアップスクリプトがある場合、バックアップ自体が暗号化・アクセス制御されているか

## 8. 依存関係・サプライチェーン (A.5.19–A.5.23 供給者関係, A.8.28)

確認項目:
- [ ] 依存関係がロックファイルでバージョン固定されているか
- [ ] 既知の脆弱性がある依存がないか（`npm audit` / `pip-audit` / `cargo audit` 等を実行して確認）
- [ ] メンテナンスされていない・出所不明のパッケージへの依存がないか
- [ ] 外部からのスクリプト直接実行（`curl | sh` 等）がビルド・デプロイ手順にないか
- [ ] CDN 参照に SRI（integrity 属性）があるか

## 9. 構成管理・変更管理 (A.8.9 構成管理, A.8.32 変更管理)

確認項目:
- [ ] 設定がコード化され（IaC・設定ファイル）、環境ごとの差分が追跡可能か
- [ ] デフォルト設定が安全側か（デフォルト拒否、デバッグ無効、最小権限）
- [ ] CORS・CSP・セキュリティヘッダの設定が過度に緩くないか（`*` 許可等）
- [ ] インフラ定義（Dockerfile, Terraform 等）で root 実行・全開放ポート・公開ストレージがないか

## 10. 脆弱性管理 (A.8.8 技術的ぜい弱性の管理)

確認項目:
- [ ] ランタイム・フレームワークのバージョンがサポート期限内か
- [ ] 依存関係の自動更新（Dependabot / Renovate 等）が設定されているか
- [ ] 既知の CVE に該当するバージョン利用がないか
