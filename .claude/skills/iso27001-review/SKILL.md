# ISO 27001 準拠レビュー

コードや設定を ISO/IEC 27001:2022 附属書A（Annex A）の管理策の観点でレビューし、逸脱・リスクを管理策番号にひも付けて報告するスキル。

**重要な前提**: これは認証審査の代替ではない。コードから観察可能な技術的管理策（主に A.8 技術的管理策と、コードに現れる範囲の A.5 組織的管理策）の準拠状況を確認するものであり、組織的・物理的・人的管理策の大半はレビュー対象外。報告書の冒頭で必ずこの限界を明記すること。

## 手順

### 1. スコープの決定

引数や文脈から対象を決める:

- **引数でパス指定あり** → そのファイル/ディレクトリを対象にする
- **引数で PR 番号指定あり** → `gh pr diff <番号>` で差分を取得して対象にする
- **引数なし・作業ツリーに変更あり** → `git diff HEAD`（未コミット変更）+ `git diff main...HEAD`（ブランチ差分）を対象にする
- **引数なし・変更なし** → リポジトリ全体の監査として実施する（規模が大きい場合は、認証情報・認可・暗号・ログ・依存関係に関わるファイルを優先する）

対象を特定したら、レビュー開始前に「何を対象にレビューするか」を一文でユーザーに伝える。

### 2. 観点別レビュー

`references/annex-a-checklist.md` を読み込み、そこに定義された観点ごとに対象コードを確認する。主要カテゴリ:

1. **アクセス制御・認証** (A.5.15–A.5.18, A.8.2–A.8.5)
2. **秘密情報・認証情報の管理** (A.5.17, A.8.24)
3. **暗号化** (A.8.24)
4. **ログ取得と監視** (A.8.15–A.8.16)
5. **セキュア開発** (A.8.25–A.8.29, A.8.31)
6. **データ保護・マスキング・削除** (A.5.33–A.5.34, A.8.10–A.8.12)
7. **バックアップ・可用性** (A.8.13–A.8.14)
8. **依存関係・サプライチェーン** (A.5.19–A.5.23, A.8.28)
9. **構成管理・変更管理** (A.8.9, A.8.32)
10. **脆弱性管理** (A.8.8)

各観点で、疑わしい箇所は必ず実際のコードを開いて確認する。grep のヒットだけで指摘しない（テストコード・サンプル・コメントアウト済みコードの誤検知を排除する）。

### 3. 指摘の検証

指摘としてまとめる前に、各候補について:

- 実際に到達可能なコードか（デッドコード・テスト専用でないか）
- 別レイヤーで緩和されていないか（例: インフラ側で暗号化、ゲートウェイで認証済み）
- 確認できない場合は「要確認」として扱い、断定しない

### 4. 報告

以下の形式で報告する。指摘ゼロの観点も「確認済み・指摘なし」として一覧に含める（網羅性の証跡になる）。

```markdown
# ISO 27001 準拠レビュー結果

**対象**: <レビュー対象の説明>
**実施日**: <日付>
**範囲の限界**: 本レビューはコードから観察可能な技術的管理策のみを対象とする。
組織的・物理的・人的管理策、および運用実態は対象外。

## 指摘事項

### [重大度] 指摘タイトル
- **該当箇所**: `path/to/file.ext:行番号`
- **関連管理策**: A.8.24（暗号の利用）
- **内容**: 何が問題か（1〜3文）
- **リスク**: 放置した場合に何が起きうるか
- **推奨対応**: 具体的な修正方針

## 観点別サマリ

| 観点 | 関連管理策 | 結果 |
|---|---|---|
| アクセス制御 | A.5.15–18, A.8.2–5 | 指摘2件 |
| 暗号化 | A.8.24 | 指摘なし |
| ... | ... | ... |

## 要確認事項
（コードだけでは判断できず、運用・インフラ側の確認が必要な項目）
```

**重大度の基準**:
- **重大 (Critical)**: 秘密情報の平文コミット、認証バイパス、暗号化なしの機微データ送信など、即時対応が必要なもの
- **高 (High)**: 管理策からの明確な逸脱で、悪用経路が現実的なもの
- **中 (Medium)**: 逸脱だが緩和策が存在する、または悪用条件が限定的なもの
- **低 (Low)**: ベストプラクティスからの乖離、将来のリスク
- **要確認 (Info)**: コードだけでは準拠可否を判断できないもの

## 注意事項

- 指摘は必ず具体的なファイル・行番号にひも付ける。一般論だけの指摘はしない
- 管理策番号は ISO/IEC 27001:2022 版を使う（2013年版の A.9, A.10 等とは番号体系が違う）。ユーザーが2013年版を使っている場合は対応表を添える
- 修正の適用はユーザーが依頼した場合のみ行う。デフォルトは報告のみ
- 秘密情報（APIキー等）を発見した場合は、値そのものを報告書に転記しない。場所と種類のみ記載し、ローテーション（無効化と再発行）を推奨する
